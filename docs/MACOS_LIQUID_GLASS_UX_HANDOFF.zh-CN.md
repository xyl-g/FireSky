# FireSky macOS Liquid Glass 与「好用」差距改造交接规范

> 文档性质：给后续产品设计 / SwiftUI / AppKit 实现 Agent 的执行交接文档
> 盘点日期：2026-11-22
> 当前产品基线：README 标记的 v1.9.9；macOS 14+，SwiftUI/AppKit + Rust FFI
> 目标范围：优先 `apps/macos/`；不重写 Rust 科学算法，不顺手改 Windows、移动端和 Web
> 核心目标：**保留 FireSky 的专业深度与暖橙品牌，把界面升级为更符合 Apple Liquid Glass 的 macOS 应用，同时补齐首次使用、结果决策、任务恢复和无障碍体验。**

## 0. 给执行 Agent 的阅读顺序与工作方式

### 0.1 先读这些文件

1. `DESIGN.md`：现有品牌色、语义色、排版、间距、组件和跨端约束。
2. `docs/MACOS_UI_BASELINE.zh-CN.md`：macOS 产品范围、科学数据口径与验收边界。
3. `README.md` 的「功能」「macOS」「数据源与注册要求」：当前功能和安装/配置成本。
4. `apps/macos/Sources/FireSkyNative/FireSkyApp.swift`：窗口、菜单命令、安装和退出守卫。
5. `apps/macos/Sources/FireSkyNative/Workbench.swift`：工作台、结果、地图和现有表面样式。
6. `apps/macos/Sources/FireSkyNative/DesignSystem.swift`：当前玻璃卡片、状态徽标、主按钮和主题 token。
7. `apps/macos/Sources/FireSkyNative/DialogViews.swift`：预检、数据管理、地形下载和设置。
8. `apps/macos/Sources/FireSkyNative/TaskHistory.swift`：历史筛选、详情、结果恢复和报告入口。
9. `apps/macos/Sources/FireSkyNative/Store.swift`：任务状态、错误映射、设置持久化；只做 UI 所必需的适配。
10. 本文全部验收清单。

### 0.2 本评估的证据边界

本文依据当前源码、README、CHANGELOG、macOS 基准文档和仓库现有 UI 截图进行静态审计与启发式评估。仓库现有截图主要来自早期 release 回放，不能替代 v1.9.9 当前构建的真机复核。

因此：

- 「已有」表示源码或发布文档中能确认能力存在，不等于每项均已完成最新真实数据验收。
- 「差距」是产品可用性和设计判断，不是用户研究统计。
- 「成熟度评分」用于排序，不应包装成精确测量结果。
- 执行 Agent 必须先构建当前版本、重新截图并走查主要流程；若实际行为与本文不一致，以真实数据合同和用户裁定为准，并在本文修订记录中说明。

### 0.3 执行原则

- 先修「看不懂、不会做、等不起、失败后难恢复」，再做视觉精修。
- 先做 macOS 基准，不以跨端同构为理由把改动扩散到全部平台。
- 优先系统标准组件和系统材质，不自制 Liquid Glass 折射、透镜或高光动画。
- 视觉改造不得改变任何预测值、科学语义、缺测语义、任务生命周期或数据删除范围。
- 每阶段独立可验收、可回退；不要一次性重写整个 Workbench。

## 1. 一句话诊断

FireSky 已经不是「功能不全的原型」：点预测、区域预测、卫星实况、预检、下载、取消、历史恢复、数据管理和应用内更新均有实际实现。

它距离「好用」主要差三层：

1. **首次成功成本偏高**：无签名安装拦截、ADS 注册/授权/Token、多源数据下载和专业参数共同抬高门槛。
2. **结果很专业，但还不够直接指导行动**：用户能看到双模型指数、最佳时刻、窗口和大量诊断，却仍要自行回答「值不值得去、几点到、两个模型不一致怎么办」。
3. **界面有玻璃外观，但还不完全是 Apple 的 Liquid Glass 层级**：当前内容卡片广泛使用 `.glassEffect`，侧栏和顶栏仍为自定义固定布局；玻璃使用范围偏宽，导航/内容层级反而可能被削弱。

**总体判断：核心流程普遍处于「能完成」到「比较可靠」之间，距离「好用」通常差一个成熟度等级；首次配置、结果决策、无障碍和主动提醒差约两个等级。不是重做产品，而是做最后一轮产品化收口。**

## 2. 「距离好用还差多少」：功能成熟度矩阵

### 2.1 评分口径

| 等级 | 含义 |
| --- | --- |
| L0 | 没有能力或仅有静态文案。 |
| L1 | 有入口，但主流程难以独立完成，或高度依赖外部文档/技术知识。 |
| L2 | 主流程可完成；状态、效率、可发现性或失败恢复仍有明显负担。 |
| L3 | 好用：普通用户能理解并完成，等待与异常可解释，结果可恢复。 |
| L4 | 高效省心：重复操作成本低，能主动提醒、快捷处理并适应不同用户。 |

核心日常流程目标至少 L3；点预测、数据准备和历史恢复目标 L4。评分是当前静态审计判断，执行前需用真实走查复核。

### 2.2 总表

| 功能点 | 当前基础 | 当前成熟度 | 距离「好用」的关键差距 | 优先级 |
| --- | --- | --- | --- | --- |
| 安装与首次启动 | 双架构 DMG、DMG 内安装引导、启动兜底、更新检查 | L2 | ad-hoc 签名触发 Gatekeeper；首次启动缺少把「选点→配置→下载→首张结果」串起来的轻引导 | P0 |
| 位置与观测参数 | 搜索、定位、地图、收藏、坐标、海拔、时区、日期和朝晚霞 | L3 | 高级字段与确认开关增加认知负担；当前输入是否有效、为何需要海拔不够直观 | P1 |
| 单点预测主流程 | 统一预检、准备、确认、计算、取消、失败保留旧结果 | L3 | 主流程完整，但准备耗时/体积/下一步的预期管理仍不足 | P0 |
| 单点结果理解决策 | GFS/EC 独立摘要、推荐窗口、指标卡、评分组成、曲线、台账和剖面 | L2–L3 | 专业信息深，但缺少一眼可懂的行动结论和双模型分歧解释 | P0 |
| 区域预测 | 预设/自定义区域、地图、固定色带、网格/城市排行、详情和冻结剖面 | L3 | 地图、工具条、详情和排行同时出现时密度高；窄窗口与结果主结论需要收敛 | P1 |
| 卫星实况 | 帧信息、指标、概率剖面、来源时效、不可用原因 | L2–L3 | 强依赖观测时间窗和卫星可用性；用户容易在非适用时刻尝试后才理解限制 | P1 |
| 数据预检与下载 | 缺失/过期/待核验分组、逐文件进度、吞吐、断点续传、取消和看门狗 | L3 | 技术透明度高，但首次下载前对时间、流量、磁盘和 CAMS 授权的预期仍不够集中 | P0 |
| 后台同步 | 可选来源、间隔、保留策略、失败补齐、手动优先、状态实时刷新 | L3 | 设置项较多；「已启用、正在同步、已欠账、为何暂停」需要更明确的状态总览 | P1 |
| 历史与结果恢复 | 独立历史页、筛选、事件、不可变快照、恢复参数、打开完整报告 | L3–L4 | 动作藏在「…」菜单；摘要、完整报告和重新预测之间的选择仍可更清楚 | P1 |
| 数据管理 | 库存、周期删除、释放预览、目录打开、SRTM 估算/下载/续传 | L3 | 库存、同步设置和数据准备分属不同位置；需要一致的入口回链和状态解释 | P1 |
| 设置 | 通用/数据/高级分类、草稿保留、锚点导航、更新和 CAMS 教程 | L2–L3 | 数据设置长且专业；Token 仅在实际下载验证，失败发生较晚；明文 0600 存储需清楚披露 | P0–P1 |
| 应用内更新 | 检查、说明、下载进度、取消、SHA256、自替换和重启 | L3 | 更新流程完整，但无签名发布的安全提示和重启预期需保持一致 | P2 |
| 键盘与 VoiceOver | 页面快捷键、部分控件标签、部分图表摘要、选中 trait | L2 | 未形成全链路键盘/ VoiceOver 验收；大量自绘图表和 `buttonStyle(.plain)` 需逐项复核 | P0 |
| 减少动态/透明度/增强对比 | 部分页签读取 Reduce Motion；系统材质有部分自动适配 | L1–L2 | 未见统一的 Reduce Transparency / Increase Contrast 策略；自绘玻璃和动画需要显式降级 | P0 |
| 多语言 | 跟随系统/中文/英文，界面文案渐进覆盖 | L2–L3 | 需检查未覆盖回退、日期/数字/日历区域设置及英文布局膨胀；不能把文案翻译等同完整本地化 | P2 |
| 主动提醒与分享 | 当前有完整 HTML 报告入口；未见系统通知、提醒计划或原生分享闭环 | L1 | 预测完成后仍要求用户主动回来查看；这是「省心」而非核心正确性的缺口 | P2 |

### 2.3 最重要的结论

- **不是缺更多指标，而是缺一个更好的默认摘要。** 专业面板继续保留，但不能成为所有用户的第一阅读层。
- **不是缺更多设置，而是缺首次成功路径。** 设置适合进阶管理，不应让新用户在预测前理解所有数据源。
- **不是缺更多玻璃，而是缺正确的玻璃分工。** Liquid Glass 应浮在内容之上，而不是成为每张内容卡片的通用背景。
- **不是缺更多动画，而是缺更一致的状态反馈。** 动效应解释来源、去向、选中和任务变化，不承担装饰 KPI。

## 3. 核心流程逐项改造建议

## 3.1 安装与首次启动

### 当前已有

- DMG 拖入「应用程序」；从 DMG 直接运行时有安装引导。
- 启动后静默检查更新，任务运行退出有确认，异常无窗口有启动兜底。
- CAMS 未配置时有提醒，并提供教程和设置落点。

### 差距

1. ad-hoc 签名意味着首次打开可能被 Gatekeeper 拦截，这是实际安装门槛，不应被视觉改造掩盖。
2. 用户完成安装后仍不知道第一次预测需要哪些账号、数据和等待。
3. 首次界面展示完整工作台与大量空指标，容易形成「功能很多，但不知道先做什么」的感受。

### 改造

- 增加可跳过的首次成功引导，不制作多页营销轮播：
  1. 选择或搜索观测点；
  2. 选择今天/明天与朝霞/晚霞；
  3. 检查数据；
  4. 若需 CAMS，集中说明注册、授权、Token 和本地存储方式；
  5. 显示下载范围、预计体积与可取消性；
  6. 得到第一张结果摘要。
- 首次空态只保留一个主按钮：「选择地点并开始预测」。已有结果或会话恢复时不显示新手引导。
- 对无签名安装继续在下载页和首次打开说明中提供官方指引；不在应用内伪造「已验证开发者」或诱导关闭安全机制。

### 验收

- 新用户不阅读 README，能从空态找到第一步。
- 无 CAMS 时明确区分「已有缓存可用」和「需要下载但不能验证授权」。
- 跳过引导后可直接进入完整工作台，并能从帮助/设置重新打开。

## 3.2 位置与参数

### 当前已有

搜索、定位、地图选点、收藏、自定义坐标、海拔与时区查询、元数据确认、今天/明天/自定义日期及朝晚霞切换均已接入。

### 差距

- 「编辑坐标」「获取海拔与时区」「已确认位置数据」偏工程化，普通用户难以理解确认的意义。
- 地图、收藏、坐标和海拔之间的关系需要更明确：修改坐标后哪些元数据会失效，应即时反馈。
- 当前地点状态使用多个小 chip，字号小且信息分散。

### 改造

- 默认只显示：地点、日期、朝晚霞；高级坐标编辑保持可展开。
- 用一行状态表达位置完整性：「位置已确认 · 海拔 43 m · Asia/Shanghai」；未确认时给出直接动作。
- 修改经纬度后立即使旧海拔/时区确认失效，并提示重新获取，不自动伪造。
- 收藏删除不能只依赖右键发现；至少在编辑收藏模式或行菜单中提供可发现入口。
- 日期控件显示数据可用范围；不可预测日期在提交前说明原因。

### 验收

- 仅通过搜索、地图或定位之一即可完成选点。
- 键盘可完成日期、现象和高级坐标操作。
- 修改任一关键输入后，旧结果继续保留，并出现明确的「结果对应旧参数」提示。

## 3.3 预检、准备与下载

### 当前已有

统一 `check → publications → prepare → forecast(confirmed=true)`；缺失、过期和待核验有状态；下载有逐文件进度、吞吐、断点续传、取消、失败重试和 15 分钟无事件看门狗。

### 差距

- 技术状态很完整，但用户最关心的「要下什么、大约多大、为什么需要、还要多久、能否取消」应更靠前。
- CAMS Token 是否有效和数据集是否授权目前主要在实际下载时验证，错误可能晚于用户预期。
- 「更新数据」「下载缺失数据」「确定预测」是正确合同，但需要让主按钮的变化更易理解。

### 改造

- 预检顶部生成一句人类摘要，例如：「还需下载 GFS 与 CAMS；EC 已可用。下载后可继续预测。」
- 在数据可提供时展示预计文件数/体积；无法估算时明确「暂时无法估算」，不得编造剩余时间。
- 分源显示状态，不把整体百分比当成唯一信息；排队时显示排队，读取时显示读取，避免都写成「下载中」。
- 主按钮只保留一个当前下一步；次动作降级，不同时让两个高亮按钮竞争。
- 周期未最新但可继续时，说明影响范围，并保留「返回更新」。
- 失败保留已完成进度和上一份有效结果；重试从既有断点/缓存合同继续。

### 验收

- 首次用户能解释当前为什么不能直接预测。
- 长任务持续有真实进度；无真实进度时使用不确定指示，不制造平滑假进度。
- 取消后界面不永久 busy，已下载数据和历史状态与引擎一致。
- 单模式失败不被另一模式覆盖或填补。

## 3.4 单点结果：从「数据展示」升级为「行动建议」

### 当前已有

GFS/EC 双摘要、0–2.5 指数、档位、最佳时刻、推荐窗口、天空时段条、指标分组、评分组成、对比曲线、逐时台账、诊断和大气剖面。

### 关键差距

用户打开应用通常先问：

1. 今天/明天值得看吗？
2. 最佳时间和推荐到达时间是什么？
3. GFS 与 EC 是否一致？
4. 主要不确定性是什么？

当前界面能回答这些问题，但需要用户在较多专业信息中自行整合。

### 改造

在结果顶部新增「行动摘要」，放在双模型详细卡片之前，但不替代它们：

- 第一行：保守、可解释的档位结论，例如「有观赏机会，但模式分歧较大」。
- 第二行：推荐窗口与最佳时刻；时间不来自客户端重算，直接读取报告。
- 第三行：主要限制因素或缺测说明，例如「EC 未完成，当前仅 GFS 可用」。
- 主行动按场景选择：「收藏该地点」「设置提醒」「分享结果」；提醒/分享未实现前不放假按钮。
- 双模型一致时强调共同窗口；分歧时并列展示，不平均、不合成虚假置信度。
- 「输入支持度」继续明确不是命中概率，禁止改写为「准确率」。

结果信息分三层：

1. **决策层**：结论、时间窗、主要风险、一个主行动。
2. **比较层**：GFS/EC 摘要和关键指标。
3. **解释层**：评分组成、趋势、台账、诊断、剖面。

### 验收

- 不展开诊断、不理解 AOD，也能说出是否值得看和何时看。
- 单模式失败、双模式分歧、缺测、旧参数结果均有独立摘要。
- 摘要不新增科学算法，不在 SwiftUI 重算指数或概率。

## 3.5 区域预测

### 当前已有

预设和自定义区域、地图绘制、跨日期变更线短弧、固定色带、缺测图例、网格/城市排行、详情、单点打开和冻结剖面。

### 差距

- 顶部工具、地图、右侧详情和排行同时出现时视觉密度高。
- 区域峰值、最佳地点和覆盖范围需要比技术元数据更早被看见。
- 详情卡大量等宽数值与小字号说明在窄窗口易拥挤。

### 改造

- 顶部工具栏最多三组：区域/绘制、日期与现象、模型与主行动。
- 地图上方提供一条区域摘要：有效格点、缺测数量、最高质量及地点；无结果时不显示假排行。
- 网格详情默认只显示关键读数，完整诊断按需展开。
- 排行支持网格/城市切换，缺测不进入有效排行；固定色带和图例保持不变。
- 窄窗口先收起详情为浮层或检查器，不压缩地图到不可用宽度。
- 选中格点、地图高亮和详情保持同一身份；清空结果时同步清理失效选择。

### 验收

- 用户能找到「最佳区域/城市」而非只看到地图颜色。
- 1120×720 下无控件重叠，地图仍可操作，详情可关闭。
- 跨 180°、单模型失败和缺测场景保持现有科学语义。

## 3.6 卫星实况

### 当前已有

卫星帧、来源与时效、指标、后验概率剖面、冻结查询、雷达不可用原因和观测窗口错误提示。

### 差距

- 实况受时间窗、扫描覆盖和数据质量限制，用户在点击后才了解限制的成本较高。
- 「实况」容易被理解为任何时候都有实时结果，需要更明确的适用性表达。

### 改造

- 页面副标题直接显示目标时刻和卫星覆盖状态。
- 非适用时间窗时在主按钮附近提前解释，不只等待引擎报错。
- 结果优先显示「当前云况是否支持朝/晚霞观测」，再展示概率剖面。
- 未知、覆盖不足、未接入和扫描过旧使用不同文案与图形，不统一成灰色。
- 雷达未接入时保持明确，不用卫星值补齐雷达指标。

### 验收

- 非观测窗口、无覆盖、扫描过旧、未知样本均有独立状态。
- VoiceOver 能获取热图整体摘要和当前选中位置读数。

## 3.7 历史、恢复与完整报告

### 当前已有

独立历史页、主动/后台筛选、事件时间线、删除确认、不可变快照、恢复已发布结果、恢复参数重查和完整 HTML 报告。

### 差距

- 「…」菜单承载关键动作，可发现性一般。
- 「恢复结果」「恢复参数重查」「完整报告」语义相近但结果不同，需要更清楚地区分。
- 右侧 360pt 详情承载较多信息时，需要避免纵向拥挤。

### 改造

- 已完成任务详情提供清晰主行动「查看该次结果」；其他动作保留菜单。
- 动作文案下补一句结果说明：恢复结果不改参数；重新检查会回到预检；完整报告打开外部窗口/浏览器。
- 快照不可用、已过期或被清理时保留任务事件，并提供可执行的下一步。
- 后台同步默认折叠保持不变，避免淹没用户主动预测。

### 验收

- 应用重启后可恢复上一份有效结果；原始缓存淘汰后按合同读取快照。
- 恢复结果不会覆盖当前未保存输入而不提示。
- 删除任务记录不删除报告和天气数据，确认文案保持明确。

## 3.8 数据管理、设置与更新

### 当前已有

库存、周期/来源删除预览、占用保护、SRTM 下载、数据目录、同步与保留、EC 来源、CAMS 教程、连通性探测、应用内更新。

### 差距

- 数据管理页与设置 → 数据之间存在跳转成本。
- 设置信息量大，锚点 chips 有帮助，但仍偏技术清单。
- CAMS Key 以明文 0600 文件保存；这是当前安全边界，应如实披露并评估是否迁移到 Keychain，不能静默宣称 Keychain 已使用。
- 更新完整，但无签名发布仍需与 Gatekeeper 指引一致。

### 改造

- 数据页提供「本次预测还缺什么」和「去准备/去同步设置」的情境回链。
- 设置每组以状态摘要开头，例如「CAMS：已配置，授权将在下载时验证」。
- 高级网络、保留和目录设置保持高级分组；普通预测不强迫用户先阅读。
- 若迁移 Keychain，作为独立安全任务完成迁移、回退和权限测试；不与视觉改造混在一个提交。
- 更新失败提供手动下载和校验路径；不隐藏 SHA256 或安装错误。

## 4. 当前 UI 与 Apple Liquid Glass 的具体差距

### 4.1 当前实现观察

1. `Workbench.swift` 使用自定义 `HStack` 侧栏 + `Divider` + 顶栏，而非完整依赖标准 `NavigationSplitView` / toolbar 行为。
2. `DesignSystem.swift` 的 `GlassCard` 在 macOS 26 上广泛使用 `.glassEffect(.regular)`，并被指标卡、库存卡等内容表面复用。
3. 为得到目标圆角，当前玻璃使用 24pt 参数、叠加边框和深色 tint；这需要重新检查是否遮挡系统材质的自适应能力。
4. 顶栏主任务进度是自定义 chip；主按钮为自定义渐变 + `.plain`，尚未利用系统玻璃按钮状态。
5. 大量辅助文本为 9–11pt，信息密度高；对高分屏、缩放和 VoiceOver 并不天然友好。
6. 窗口默认 1440×900，最小 1120×720；区域页、设置页和结果页需要分别验证，不可只验首页。
7. Reduce Motion 已在部分页签读取，但设置锚点等仍有动画入口；Reduce Transparency / Increase Contrast 需要统一审计。

### 4.2 方向性结论

**更靠近 Apple 的关键不是把现有 GlassCard 做得更透明，而是：**

- 把 Liquid Glass 从普通内容卡片撤下；
- 让侧栏、工具栏、菜单、popover 和关键控件使用系统 Liquid Glass；
- 内容区使用稳定表面与标准材质；
- 使用同心圆角、滚动边缘效果和背景延展建立空间关系；
- 让系统根据背景、焦点、输入方式和辅助功能设置调整材质。

## 5. 目标设计原则

### 5.1 Apple 三原则在 FireSky 中的落地

| 原则 | FireSky 落地方式 |
| --- | --- |
| Hierarchy / 层级 | 内容稳定，导航与关键控件悬浮；行动摘要高于指标；指标高于诊断。 |
| Harmony / 和谐 | 窗口、侧栏、工具栏和弹层使用同心圆角；暖橙只强调关键动作与选中，不覆盖所有玻璃。 |
| Consistency / 一致 | 相同状态在各页使用相同组件、文案和动效；标准 macOS 菜单、快捷键、焦点和窗口行为优先。 |

### 5.2 FireSky 不变的品牌和科学语义

- 保留暖橙品牌，不改成 Apple 蓝色作为全局主题。
- 保留浅色天空氛围和深色夜空蓝，但降低内容区背景噪声。
- 保留 GFS / EC 独立展示、0–2.5 固定质量量纲、三组图表语义色和缺测灰。
- 不引入新的数据色相，不用玻璃颜色表达预测好坏。
- 所有界面文案为简体中文；英文模式使用同一信息层级，不缩短科学含义。

## 6. 材质与表面层级规范

> 本节数值是项目建议，不是 Apple 官方内部 token。macOS 26+ 优先系统材质，不应为了匹配数值而重绘系统玻璃。

| 层级 | 用途 | macOS 26+ | macOS 14–25 回退 | 禁止事项 |
| --- | --- | --- | --- | --- |
| C0 内容基底 | 窗口正文、结果页、设置内容 | 稳定页面背景；不使用 Liquid Glass | 同左 | 不让正文、表格和图表直接压在复杂高对比背景上 |
| C1 内容分组 | 指标组、表单、库存、诊断卡 | 实体或高遮蔽标准表面；hairline 分隔 | `.regularMaterial` 或控制背景色 | 不对所有卡片调用 `.glassEffect` |
| N1 导航 | 主侧栏、可展开的导航区域 | 标准 split view / sidebar 的系统 Liquid Glass | `.regularMaterial` | 不叠多层自定义 tint，不用透明降低选中可读性 |
| N2 工具与关键控件 | 工具栏按钮、分段、搜索、主行动 | 系统 toolbar、`.glass` / `.glassProminent` 等标准样式 | 标准 bordered / prominent 控件 | 不给每个文本标签、状态 chip 加玻璃底 |
| O1 临时浮层 | 菜单、popover、日期选择、轻量详情 | 系统菜单/popover 材质 | 系统标准材质 | 不玻璃套玻璃，不让长文浮层过度透明 |
| M1 模态任务 | 预检、删除确认、关键警告 | 系统 sheet/alert，稳定可读背景 | 同左 | 不让背景内容影响危险操作和错误阅读 |

### 6.1 Regular 与 Clear

- 默认只使用 **Regular**：侧栏、工具栏、含文字的弹层都需要可读性调节。
- **Clear** 仅考虑用于地图或影像上方少量、短标签的浮动控件；必要时添加遮蔽层。
- 不在同一浮层混用 Regular 与 Clear，不用 Clear 承载长设置表单、预检或错误说明。
- 地图上的控件仍须满足对比度；地图复杂不能成为使用 Clear 的充分理由。

### 6.2 半透明、模糊与着色

- 半透明负责空间连续性，模糊负责减弱背景细节，着色负责稳定对比；三者不可互相替代。
- 不硬编码统一透明度来模拟所有环境；优先让系统按下方内容和辅助功能设置调整。
- 内容卡片若使用标准材质，应选择语义相符的厚度，而不是为了「更玻璃」选最薄材质。
- 暖橙 tint 只用于一个主要行动、当前选中或少量状态，不给整个侧栏和所有按钮同时着色。
- 背景色与图表色继续成对维护 light/dark，并验证增强对比设置。

### 6.3 边界、光影与圆角

- 内容卡以 1px 级低对比 hairline 和间距分组为主，不叠加明显外发光。
- 悬浮层的深度由系统阴影、材质和滚动边缘共同表达，不添加粗黑描边。
- 使用同心圆角：内层圆角随外层圆角和间距收缩；不要全界面胶囊化。
- macOS 高密度控件继续使用圆角矩形；大型、独立主行动才考虑胶囊形。
- 保持现有卡片约 16pt、普通控件约 8pt、chip 约 6pt 的视觉节奏；macOS 26 的系统组件以系统度量为准，不再用经验参数反推系统内部圆角。

## 7. 窗口、导航和工具栏改造

### 7.1 窗口

- 优先评估 `NavigationSplitView` 或 AppKit 等价标准结构，而非继续扩张自定义侧栏逻辑。
- 若短期保留自定义根布局，也必须实现：可隐藏侧栏、清晰选中态、窗口缩放、键盘焦点和内容安全区。
- 页面标题描述当前内容，不仅重复应用名。
- 非活跃窗口不通过大幅降低透明度表达失焦。
- 不为 Liquid Glass 改造调整科学数据的最小窗口要求；若降低最小宽度，必须单独通过全部页面验收。

### 7.2 主侧栏

- 单点、区域、实况是核心导航；数据管理和任务历史保持独立；设置位于固定但低干扰位置。
- 选中态使用稳定底色 + 字重/选中标记，不能只有暖橙文字。
- 更新徽标保留，但增加 VoiceOver 文案，不只显示绿点。
- 支持系统侧栏尺寸变化和用户隐藏/显示；关键操作不能放在侧栏底部唯一位置。
- 侧栏图标优先 SF Symbols，保持单色层级；不为每个页面使用不同颜色。

### 7.3 顶栏与工具栏

- 将真正操作当前内容的控件纳入系统 toolbar；页面标题与全局任务状态保持低干扰。
- 工具栏最多三组，主行动位于稳定的 trailing 区域。
- 窗口变窄时按优先级进入系统 overflow，不缩小到难以点击。
- 工具栏中的命令应在菜单栏有等价入口；侧栏页面快捷键继续保留。
- 状态文字、同步状态和非交互信息不伪装成玻璃按钮。
- 内容滚动到工具栏下方时使用系统 scroll edge effect；有固定表头时选择更明确的硬分隔。

### 7.4 菜单与弹层

- 使用系统菜单、popover、sheet 和 confirmation dialog，不重新设计一套通用玻璃弹窗。
- 日期选择、格点轻详情可用 popover；预检、删除和关键授权使用稳定模态。
- 菜单项维持紧凑行高、快捷键和禁用原因；选中不只靠透明度。
- 弹层从触发控件附近出现，关闭后焦点返回触发控件。

## 8. 组件与反馈状态规范

### 8.1 按钮

- 每个区域最多一个主要行动；使用 `.glassProminent` 或系统 prominent 样式时仍保留 FireSky 暖橙的节制强调。
- 次级按钮使用普通玻璃或 bordered/borderless，不全部使用渐变。
- 破坏性操作使用系统 destructive 角色与确认，不仅靠红字。
- 禁用状态必须可解释；关键禁用按钮提供 hint 或邻近原因。
- 不用 41pt 高、全宽渐变按钮覆盖所有场景；工作台主行动可保留强调，工具栏动作按系统尺寸。

### 8.2 分段、输入和选择器

- 分段选择用于少量互斥枚举；选中态同时有底色和文字/符号变化。
- 搜索框、Token 输入和坐标输入使用稳定表面，确保插入点和焦点清晰。
- 长路径中间截断并可复制；错误文本可选择。
- 输入非法时在提交前指出字段和修正方式，不仅返回引擎原始错误。

### 8.3 状态徽标与任务反馈

- 保留五态 StatusChip 的图标 + 文案，不只靠颜色。
- 全局任务状态在切页后仍可见，但只保留一个主进度入口，避免顶栏和参数区重复竞争。
- 排队、下载、校验、计算、取消中和失败是不同状态，不统一写成「加载中」。
- 进度无真实数据时使用不确定指示；不用假百分比。
- 完成反馈短暂且不打断；失败提供下一步和可复制细节。

### 8.4 内容卡片、图表和地图

- 内容卡不再是 Liquid Glass 展示区；它们负责稳定阅读。
- 概览减少同等重量的小卡数量，优先建立摘要—比较—解释的纵向层级。
- 图表保留缺测断线、固定量纲和语义色；玻璃背景不得影响网格线与标签对比。
- 自绘图表提供 VoiceOver 摘要、选中值和必要的文本等价物。
- 地图浮层控制在少数工具与详情；不清空地图主体来叠放玻璃卡片。

### 8.5 空态、加载和错误

- 首次空态教用户完成第一步；已有结果空态不能清空有效内容。
- 无收藏、无历史、无库存、无结果分别使用不同文案和动作。
- 加载保留布局稳定，避免玻璃卡片出现/消失造成大幅跳动。
- 错误保持「发生了什么 + 下一步 + 可复制细节」，不只用红色文本。

## 9. 动效与感官反馈

### 9.1 原则

- 动效解释状态变化，不为展示材质而持续运动。
- 触控板/鼠标反馈应比直接触摸更克制；不照搬 iOS 的大幅弹性。
- 高频 hover 不做明显缩放、发光或折射。
- 任何任务都不能等待装饰动画结束后才可操作。

### 9.2 项目建议时值（非 Apple 官方 token）

| 场景 | 建议 | 说明 |
| --- | --- | --- |
| hover / 颜色反馈 | 80–120ms | 只改底色、亮度或符号状态 |
| 按下 / 释放 | 60–100ms | 极轻微，不做大幅缩放 |
| 页签与小型状态切换 | 150–180ms | 延续当前 180ms 节奏，但支持 Reduce Motion |
| 菜单 / popover | 140–200ms | 从触发点出现，关闭更快 |
| 侧栏 / 检查器布局 | 200–280ms | 保持内容位置可追踪，低回弹 |
| 结果更新 | 短淡入 + 局部内容替换 | 不让整页重新飞入 |

### 9.3 Reduce Motion

- 移除 matched-geometry 大位移、弹簧回弹、装饰高光流动和自动滚动动画。
- 保留即时状态、短淡入淡出和焦点变化；重要信息不能只靠动画表达。
- 统一封装动画决策，不让每个视图自行判断是否读取辅助功能设置。

## 10. 明暗模式、可访问性与本地化

### 10.1 明暗模式

- 浅色：内容表面偏稳定乳白/控制背景，阴影轻，文字不使用过低透明度。
- 深色：沿用夜空蓝，但避免高亮白边和暖橙大面积发光；玻璃边界低亮、文字高对比。
- 两套主题分别检查内容图片、地图、图表和系统材质，不做简单反色。
- 系统材质在明暗环境间自适应时，自定义 tint 不得阻止其调整。

### 10.2 对比、字号和焦点

- 正文以至少 4.5:1 验证，大文本和关键非文本图形至少 3:1。
- 逐步将 macOS 正文从 12pt 过渡到约 13pt；辅助说明优先 11–12pt。现有 9pt 文本只可在充分验证后保留极少数非关键装饰信息，不能承载状态、错误或操作。
- 支持系统文本尺寸/缩放行为；不得只通过 `minimumScaleFactor` 把内容继续缩小来避免重排。
- 所有功能可通过键盘完成；焦点环清晰，焦点顺序符合视觉顺序。
- 图标按钮有标签，选中/禁用/忙碌状态有辅助功能表达。

### 10.3 Reduce Transparency / Increase Contrast

- Reduce Transparency：切换为更稳定、更高遮蔽的表面，保留相同层级与功能，不是简单禁用整个窗口透明度。
- Increase Contrast：强化文字、边界、焦点和图表关键线，不是单纯加深全局背景。
- 系统标准组件优先自动适配；自绘 `GlassCard`、地图浮层、图表和状态 chip 必须单独测试。

### 10.4 VoiceOver

至少覆盖：

- 页面导航、当前页、更新徽标；
- 选点、日期、现象、坐标有效性和主按钮禁用原因；
- 预检每一数据源状态与下一步；
- 双模型摘要、行动建议、缺测和旧参数提示；
- 图表整体摘要、当前选中值和文本等价内容；
- 地图格点详情的文本入口；
- 历史筛选、任务状态、恢复/重查/删除动作；
- 设置草稿保存、CAMS 状态和更新进度。

### 10.5 本地化

- 中文与英文都走完整主流程，不只做字典存在性检查。
- 检查英文按钮、工具栏、侧栏和 360pt 历史详情的文本膨胀。
- 日期、时间、数字和日历使用正确 locale；当前固定中文环境的做法需要与语言策略一并复核。
- 未翻译回退中文必须可诊断，不能在中英混排中无意出现引擎键名。

## 11. 不同窗口尺寸与性能

### 11.1 响应式优先级

至少验收 1440×900、1280×800、1120×720，并补一个大屏场景。

窗口变窄时按以下顺序让位：

1. 收起非关键检查器/详情；
2. 低频工具进入 overflow；
3. 收起主侧栏；
4. 结果指标由多列变少列；
5. 保持主行动、核心摘要和当前任务状态可见。

禁止：

- 为保留三栏把地图和正文压到不可用；
- 用更小字号解决所有拥挤；
- 横向滚动整个页面；
- 让工具栏主行动默认进入 overflow。

### 11.2 性能预算

- 优先系统材质，避免全屏多层实时模糊、玻璃重叠和逐帧改变模糊半径。
- 滚动、窗口 resize、地图拖动和图表 hover 时重点检查过度重绘。
- 动画优先 transform/opacity；不对大面积阴影、模糊和折射同时做逐帧动画。
- 静态内容表面尽量实体化；无交互时不运行装饰动画。
- 使用 Instruments / os_signpost 检查主线程、SwiftUI 更新和渲染；不能仅凭截图宣称性能提升。
- macOS 14–25 回退路径不得产生两套业务行为；材质不同，功能和状态一致。

## 12. 推荐实现路线

### 12.1 技术策略

- macOS 26+：使用标准 SwiftUI/AppKit 组件自动获得 Liquid Glass；必要时才使用 `.glass`、`.glassProminent`、`.glassEffect`。
- macOS 14–25：使用标准材质和系统控件回退；不自制高成本透镜/折射。
- 标准 split view、toolbar、sheet、popover、menu 优先于继续扩张自定义外观。
- 内容卡片先移除通用 `.glassEffect`，改为稳定内容表面；这是「更 Apple」而不是「倒退」。
- 自定义图表和地图无需为了玻璃化重写；只调整周边工具、详情、选中反馈和可访问性。
- 保留 Rust FFI 与 Store 业务合同；UI 层不得新增科学算法和跨模式补齐。

### 12.2 不建议的做法

- 不建议一次性把所有视图换成 NavigationSplitView 后同时改所有结果布局。
- 不建议为每张卡片增加高光、折射和浮动动画。
- 不建议复制 Apple 私有材质参数或依赖未公开 API。
- 不建议把系统玻璃用在长表单、逐时台账、图表细胞和大段错误说明上。
- 不建议为了视觉统一删除 macOS 的密度、键盘快捷键和菜单命令。

## 13. 分阶段 backlog

## P0：先达到「看得懂、能成功、可恢复」

1. 当前版本重新构建并走查点/区域/实况/数据/历史/设置，更新真实截图与差距矩阵。
2. 设计并落地单点「行动摘要」，覆盖双模型一致、分歧、单模式失败、缺测和旧参数。
3. 收敛首次空态和首次成功路径；补齐 CAMS/下载前置说明，不增加营销轮播。
4. 预检突出下一步、下载范围与状态；保持所有真实进度和取消合同。
5. 全文审计 9–10pt 关键说明、焦点、禁用原因和 VoiceOver。
6. 建立 Reduce Motion / Reduce Transparency / Increase Contrast 的统一测试矩阵。

**P0 完成标准：** 新用户能完成首次预测；老用户能一眼得到行动结论；失败和取消可恢复；核心流程键盘/VoiceOver 走查无阻断。

## P1：建立正确的 Liquid Glass 层级

1. 新建内容表面与导航表面的明确组件边界，内容卡退出通用 `.glassEffect`。
2. 主侧栏和工具栏逐步迁移或对齐系统行为；加入隐藏侧栏、overflow 和 scroll edge 验证。
3. 结果页按决策层/比较层/解释层重排，不减少已有专业信息。
4. 区域页收敛工具组、摘要和详情；实况提前说明适用时间窗。
5. 设置增加状态摘要与数据页回链；历史详情提升主要动作可发现性。
6. 完成浅色、深色、1120×720 和大屏验证。

**P1 完成标准：** 玻璃集中在导航/控件层；内容更清晰；窗口缩放不依赖缩小字号；所有主要页面有完整状态截图。

## P2：从「好用」到「省心」

1. 基于既有结果快照设计系统通知/提醒：用户显式开启，说明权限、时区和取消方式。
2. 提供原生分享或导出摘要；分享内容包含地点、目标日期、模型状态、来源时效和缺测说明。
3. 完善中英文布局、日期/数字 locale 和未翻译回退诊断。
4. 评估 CAMS 凭据迁移 Keychain；独立迁移与验收，不和 UI 提交混合。
5. 用真实用户任务测试验证首次成功率、结果理解、历史恢复和提醒价值。

**P2 不是伪造承诺：** 若通知、分享或 Keychain 尚未实现，界面不得出现不可用按钮或虚假设置。

## 14. 验收矩阵

### 14.1 必测业务场景

| 场景 | 必须验证 |
| --- | --- |
| 首次无缓存 | 引导、CAMS 说明、预检、下载、取消、重试和首个结果 |
| 有缓存离线 | 可用范围明确；缺数据不伪造；旧结果可查看 |
| 点预测双模型完成 | 行动摘要、独立读数、推荐窗口、来源与周期 |
| 单模式失败 | 不平均、不填补；另一模式仍可使用；错误可复制 |
| 参数改变 | 旧结果保留并标 stale；可恢复原始参数或重新预检 |

| 实况非窗口/覆盖不足 | 提前说明与引擎错误一致；未知不解释为晴空 |

| 删除数据/记录 | 范围、文件数、释放、占用跳过和保留内容准确 |

- 1440×900 / 1280×800 / 1120×720 / 大屏。

- 键盘全流程 / VoiceOver 核心流程。

- 改动范围与未改动范围。

## 15. 不可破坏的产品合同

执行 Agent 必须保持：

1. GFS / EC 独立，不平均、不跨模式填补失败。
2. 缺测不填零，不参与有效排行；输入支持度不是命中概率。
3. 预测值、评分组成、剖面和推荐窗口来自 Rust 报告，UI 不重算科学算法。
4. 预检按本次请求验证科学字段、空间和时间覆盖；库存存在不等于准备成功。
5. 失败和取消不覆盖上一份有效结果；中断任务不静默自动重跑。
6. 后台同步默认关闭；手动任务优先；长任务必须可取消并有真实状态。
7. 删除预览和实际范围一致；占用文件跳过；报告和任务记录按合同保留。
8. 结果恢复与短期计算缓存分开；冻结剖面有独立寿命。
9. 凭据、Key、Token 不写入仓库、截图或日志；现有明文存储不得被描述为 Keychain。
10. 不用无签名安装绕过说明诱导用户关闭系统安全机制。

## 17. 预期体验提升

- **首次使用**：从「先研究数据源和设置」变成「沿一条可跳过路径得到首个结果」。
- **结果理解**：从「阅读两组专业仪表盘」变成「先得到行动结论，再按需深入证据」。
- **视觉层级**：从「所有卡片都在玻璃上」变成「内容稳定、导航悬浮、关键动作明确」。
- **等待体验**：从「盯着百分比」变成「知道当前阶段、数据来源、取消和恢复后果」。
- **重复使用**：从历史、收藏和提醒形成闭环，减少每次重新选点与主动查看。
- **系统体验**：键盘、VoiceOver、辅助功能、窗口缩放和明暗模式成为一等能力。
- **性能与品质感**：减少无效玻璃叠加和装饰动画，让精致感来自响应、对齐和可读性，而非特效数量。

最终目标可以概括为：

> **先回答「现在该做什么」，再展示「为什么」；Liquid Glass 负责建立空间与交互层级，FireSky 的专业数据负责建立信任。**
