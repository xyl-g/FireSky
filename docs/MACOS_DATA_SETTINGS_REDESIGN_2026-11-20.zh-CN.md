# macOS 数据、设置与任务历史改进方案

日期：2026-11-20  
源码基点：`da40c34`，以本次读取的工作区源码为准。  
状态：**阶段 A 已于 v1.2.0 实施交付**（历史独立页面、设置分类、探测与同步迁移、
顶栏修正、说明收敛，本地快照验收通过）；阶段 B（目录迁移）、C（手动删除）、
D（SRTM 独立下载）尚未实施，以下方案仍为设计与验收口径。

## 1. 需求理解与结论

本方案将“人物历史”理解为“任务历史”。“独立一个框”建议落实为侧栏独立页面，
使历史具有自己的列表与详情区，不再嵌入数据页底部。设置中的“独立数据框”则落实为
设置内的独立“数据”分类，和通用、位置、引擎分开切换，避免只给长表单增加边框。

需要同时解决六件事：

1. 任务历史独立，支持快速寻找、恢复、重试和删除记录。
2. 数据管理支持按数据源、周期或瓦片手动删除，显示实际释放空间。
3. 下载连通性与后台同步统一归入“设置 → 数据”，设置本身按类别拆页。
4. SRTM 有明确的下载按钮、下载范围和任务反馈，不只提供来源选择。
5. 用户选定的数据目录直接放可见的分类目录，取消隐藏的 `.cache` 层。
6. 去掉无关地点、重复说明和技术噪声，保留必要的状态、错误及操作反馈。

优先完善 macOS；共享 Rust 路径与接口变更需列出其他端的兼容影响，但本方案不代表
同步启动所有平台的 UI 改造。既有产品约束见 [macOS 基准](MACOS_UI_BASELINE.zh-CN.md)。

## 3. 页面结构

```text
主侧栏
  单点预测
  区域预测
  实况观测
  数据管理
  任务历史
  ────────
  设置

设置分类                 当前分类内容
  通用                   主题
  数据                   下载源 / 账号 / 连通性 / 同步 / 存储与保留
  位置与海拔             海拔来源
  高级                   引擎与诊断
```

设置采用固定宽度分类栏与右侧内容区，窄窗口可用原生分类选择器，切换时只显示一个分类。
“数据”内各区使用标题、留白和分隔线组织，不叠放多层卡片。账号教程、同步高级参数、
探测详情默认折叠；同步来源开关、间隔、区域和保存操作保持可见。

顶栏按页面明确生成：预测页显示地点；区域页显示区域；数据管理、任务历史和设置
只显示对应标题。删除无关的地点副标题和装饰性当天日期。任务进行中仍保留必要的进度
及取消入口，切页不会丢失任务状态。

## 4. 任务历史独立

- 新增 `Page.history`，同步更新页面路由、侧栏、菜单、快捷键映射及持久化页面值解析。
- 主区为历史列表，选中后用右侧详情区显示摘要与事件；窄窗口切换详情，提供返回入口。
- 默认突出主动任务，后台同步用筛选开关显示；新增类型、状态筛选及加载更多。
- 列表仅显示任务类型、地点或区域、时间、状态；耗时、来源、原始 UTC、技术事件进详情。
- 恢复结果、恢复参数并重新检查、删除记录三种动作名称与提示明确区分。
- “删除记录”沿用现有语义：不删除报告和天气数据。释放磁盘空间必须去数据管理操作。
- 页面离开后任务继续；重新进入恢复选中项、滚动位置与筛选，已删除项则清除选择。

首批独立页面可复用现有历史能力，但不能原样保留外层套内层的滚动布局。
分页若需扩展引擎契约，应单独实现，不能只在前端隐藏超过现有读取上限的记录。

## 5. 数据管理与手动删除

### 5.1 主页面

顶部只保留实际数据目录、已统计占用、刷新和打开目录。尚未覆盖所有类别时，明确标注
“已统计占用”，避免把三个模式数据的总和称为整个目录的总占用。

| 分类 | 默认行信息 | 展开内容与操作 |
| --- | --- | --- |
| GFS / EC / CAMS | 周期数、占用 | 周期、文件数、大小；选择周期删除；清空该源 |
| 卫星 | 扫描数或时间范围、占用 | 按扫描或日期管理 |
| 地形 SRTM | 瓦片数、占用 | 瓦片名与覆盖范围；下载、删除 |
| 已发布结果与报告 | 数量、占用 | 查看、删除；说明历史恢复影响 |
| 可重建计算与地图缓存 | 占用 | 按类别清理；保护仍被结果引用的资源 |

库存状态使用“已有本地文件”“无数据”等中性表述。是否满足某次预测仍由请求预检判断，
文件数量、下载探测通过或凭据已保存均不等于数据已齐。

### 5.2 删除行为

1. 用户选择数据源及周期、扫描或瓦片，点击垃圾桶按钮；支持多选。
2. 引擎预览待删对象、文件数、预计空间、受保护对象及影响。
3. 确认框显示具体范围，例如“删除 GFS 的 2 个周期，预计释放 1.3 GB”。
4. 执行时再次核验对象身份和占用；预览失效时刷新预览，不能静默扩大删除范围。
5. 完成后分别显示已删除、正在使用而跳过、失败数量及实际释放空间，刷新库存和相关状态。

删除规则：

- Swift 发送引擎生成的对象 ID，不传任意磁盘路径或自行递归删除目录。
- 按完整资源组删除数据及其索引、清单、派生产物；不留下“文件没了但清单仍显示可用”的状态。
- 和前台计算、下载、后台助手共享跨进程占用保护；仅检查 `store.busy` 不够。
- 复用并核查现有文件锁、快照租约与地图引用保护。锁标记存在与真实读者占用的语义需分别核对。
- 删除原始天气数据后，已有独立结果快照可继续恢复；依赖原始输入的剖面或重算需如实提示缺数。
- 删除报告、快照会影响历史恢复，确认时单独说明；默认不连带删除任务记录。
- 删除后使相关预检会话失效，确认计算前重新检查，不能沿用删除前的 ready 状态。
- 自动同步开启时，最新周期可能再次下载；确认框对此作简短提醒，提供跳转同步设置。
- 首批采用明确确认后的永久删除，不承诺撤销。不能把仅移到同盘隐藏目录算作释放空间。

现有 `native_data::prune` 按文件年龄和扩展名处理，不能直接承担上述桌面按周期删除。
现有保留策略负责自动淘汰，可复用其中保护逻辑，但要新增手动删除的对象范围与接口。

建议新增契约（名称暂定，均为待实现）：`data_delete_preview`、`data_delete_execute`。
返回结构应包含稳定资源 ID、清单版本或预览标识、分类、统计、跳过原因及逐项失败原因。

## 6. 设置中的独立“数据”分类

| 分区 | 常驻内容 | 次级内容 |
| --- | --- | --- |
| 下载源 | EC 来源选择 | 各源域名及来源说明 |
| CAMS 账号 | 已配置/未配置、Token 输入与保存、删除凭据 | 配置教程、配置来源、覆盖原因 |
| 下载连通性 | 检测按钮、每源通过/失败、检测时间 | 域名、耗时、字节数、完整错误、复制报告 |
| 后台同步 | 总开关、来源、间隔、区域、立即同步、保存及摘要状态 | 时效上限、逐源状态、后台助手管理 |
| 存储与保留 | 数据目录、选择/打开/迁移；自动保留策略 | 目录诊断与迁移详情 |

“立即同步”随同步配置一起从数据页移入这里，避免出现两套相同控制。
数据页可提供“同步设置”跳转链接，但不重复摆放完整设置。

连通性检测只在用户点击时发起，保留取消、失败重试和报告复制。未检测使用中性状态，
取消数据侧栏红点；通过只代表该次下载样本成功，不替代预测预检。

保存规则要可见且一致：来源、同步、保留等需要提交的表单显示未保存状态和本区保存操作；
主题等即时设置直接生效。切换分类保留草稿，立即同步只消费已保存配置。
修改来源后，旧连通性结果标记为过期，不能继续显示为当前配置通过。

数据目录从“本地引擎”移到“数据 → 存储与保留”。自定义引擎路径留在高级分类，
不让普通用户把选择数据目录误认为必须配置引擎。

## 7. SRTM 显式下载

海拔来源选择保留在“设置 → 位置与海拔”，选项简化为“自动 / 在线 / 本地 SRTM”，
具体回退规则放帮助。选择来源只保存策略，不应立即下载或悄悄修改预测位置。

下载入口放“数据管理 → 地形 SRTM”；设置里提供跳转“管理地形数据”。下载面板
明确显示目标地点、坐标、需要的瓦片和本地状态，并提供“下载缺失瓦片”按钮。
这里显示坐标有明确下载用途，与设置公共顶栏无关坐标不同。

首批支持当前选定地点对应瓦片；没有有效地点时提供“选择地点”操作。
后续可扩展按区域下载，届时必须先计算瓦片数量、预计体积并限制过大范围，不能默认下载全国。

状态包括：未下载、已存在、下载中、取消中、已取消、成功、失败、不在覆盖范围。
下载后更新库存和位置数据可用性；不直接覆写用户的手动海拔，也不触发预测。

引擎已有 `.hgt.gz` 下载、锁、解压校验、临时文件发布及本地复用。当前下载附着于
`metadata`，返回海拔和时区，且现有下载期间的取消检查并非连续字节级响应。
建议在同一下载实现上增加独立地形任务接口，避免 UI 为下载而调用会回填地点的元数据流程。

建议接口（待实现）：`terrain_inventory`、`terrain_download`，后者发出真实阶段进度并支持取消。
拿不到总长度时显示不定进度，不能伪造百分比。现有覆盖条件为 `-56 <= 纬度 < 60`，
超界提示不可用，不能以零海拔冒充有效数据；下载大小以实际清单或响应估算，不写死“每块几 MB”。

## 8. 可见数据目录与迁移

用户选择的目录就是 FireSky 数据根目录，建议新布局如下，名称表达实际用途：

```text
FireSkyData/
  gfs/
  ecmwf/
  cams/
  himawari-hsd/
  srtm/
  locations.json
  point-forecasts/
  regional-forecasts/
  map-frames/
  reports/
  settings/
  state/
```

不再新增 `.cache` 包裹层；设置与状态最终也使用可见目录，不把隐藏层从 `.cache`
换成另一个名字。下载过程必要的临时文件和锁仍由引擎管理，不需要作为普通用户资源展示。
报告内部结构、快照引用及校验内容不能仅为改名而破坏。

### 8.1 路径统一

建立 Rust 统一目录解析入口，下载、库存、预检、计算、清理、任务历史、结果恢复、
位置查询和同步共用。显式环境变量覆盖继续有效，UI 显示实际解析的目录。
Swift 后台助手的状态/日志路径与安装配置也要使用同一版本的布局合同。

不能只改 `desktop_runtime.rs`：`native_data.rs`、`desktop_inventory.rs`、
`cache_retention.rs`、位置配置及其他消费者仍有各自默认值，单点改动会导致读写分叉。
实现前需盘点所有活动入口，旧测试 fixture 和归档文档中的 `.cache` 不做盲目全局替换。

### 8.2 旧目录升级与切换

1. 检测根目录布局版本，识别旧 `.cache` 与 `.firesky`，生成迁移清单和空间估算。
2. 提供“迁移已有数据”与“使用空的新目录”两个明确操作；说明旧数据仍在原处。
3. 暂停新任务并协调应用内同步、外部助手及活跃读写，取得跨进程迁移保护。
4. 同卷优先移动；跨卷分批复制并校验。新旧同名文件冲突需核验，不能直接覆盖。
5. 更新允许重定位的路径引用，验证报告、快照、清单和历史恢复；不可变快照不能随意改写。
   对已写入的绝对旧路径，保留兼容解析或建立受控映射，具体方案须先审计引用合同。
6. 校验成功才切换布局标记、工作区配置与后台助手；失败可回到原布局并继续使用。
7. 确认迁移完成后再清理已核验旧副本。迁移中断可恢复，显式覆盖到外部目录的路径不擅自搬迁。

新版本统一写新布局；旧布局只用于受控兼容读取和迁移，不让两个布局长期独立写入。
切换数据根目录还要同步刷新库存、历史、同步状态并清除旧目录预检会话。

## 9. 简洁化规则与细节

| 内容 | 改进 |
| --- | --- |
| 设置顶栏地点、经纬度 | 移除，按页面输出标题 |
| 设置中的“当前实际海拔来源” | 移到地点详情；设置只说明选择的策略，避免历史查询状态冒充配置 |
| 同步和来源长段说明 | 缩成必要一句；约束放输入校验、单位和帮助 |
| 账号教程、launchd 细节 | 折叠；默认展示是否配置、是否运行及可操作按钮 |
| 探测成功后的域名、字节和耗时 | 默认收起，失败原因保留可见，全文可复制 |
| 保存成功提示 | 本区短暂显示，不长期占位；失败持续显示至解决或再次操作 |
| 空态与加载 | 区分无数据、读取中、断开、失败；不让空库存永久显示转圈 |
| 全局错误 | 归属本次操作和所在分区，避免预测错误出现在设置 |
| 单位和数字 | 容量单位和精度一致；经纬度按正负显示 N/S/E/W，检查现有固定 N/E 文案 |
| 禁用与任务 | 显示具体原因；页面可浏览，冲突写操作按实际资源禁用 |

简洁化不能删掉必要反馈：删除影响、下载目标、同步失败、数据缺失和不可恢复原因必须可见。
长路径可中间截断并提供复制/打开，错误可展开和复制；图标按钮必须有帮助和辅助功能名称。

## 10. 实施顺序与验收

| 阶段 | 工作 | 完成条件 |

| A：界面结构 | 历史独立、设置分类、探测与同步迁移、顶栏修正、说明收敛 | 六个主页面路由正确；设置不再出现无关地点；草稿和任务状态不因切页丢失 |

| C：数据操作 | 扩展库存、手动删除预览/执行及占用保护 | 按对象删除、准确统计；跨进程冲突可解释；旧预检失效；历史恢复符合影响说明 |
| D：地形下载 | 独立 SRTM 任务与下载 UI | 缺失下载、缓存复用、失败、超界、取消、重新进入查看均可验证 |

阶段 A 可先独立交付；阶段 C/D 依赖阶段 B 的目录合同。删除和下载接口可提前设计，
但不得在迁移规则尚未确定时形成另一套路径默认值。

重点验收场景：

- 设置、数据和历史页无杭州坐标泄漏；预测页地点和历史结果身份仍准确。
- 任务进行中切换页面，取消和进度仍可找到，返回历史无需穿过数据列表。
- 连通性检测保留取消和报告；来源修改使旧检测过期；同步只使用已保存设置。
- 无库存、断开、权限不足、磁盘空间不足各有明确状态。
- 删除一个周期、多选、整源、占用中、预览后数据变化、部分失败均验证；不越过受管目录。
- 同步助手运行时删除或迁移，不损坏下载与索引；自动同步重下行为符合提示。
- 删除原始缓存后恢复已有结果；删除结果资源后显示准确不可恢复原因；剖面缺失不伪造。
- SRTM 已存在不重复下载，超界不下载，失败不发布半成品；取消延迟有可验证的上限。
- 新装、旧布局、部分迁移、新旧目录冲突、外部环境覆盖、跨卷迁移、重启恢复均验证。
- 1440×900、1120×720、窄窗口、浅深主题下无文字遮挡；键盘和 VoiceOver 可完成主要操作。
