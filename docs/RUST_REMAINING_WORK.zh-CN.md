## 阅读口径

- 默认生产 HTTP、CLI、桌面引擎和 Docker 启动命令已经改为 Rust，无 Python 回退。
- “缺实现”表示原生功能尚未完成；“缺验收”不能推断功能不可用，也不能当作已完成。
- “优化项”不阻止当前原生主链运行，不能混同为仍依赖 Python。
- P0：阻止完整退役/正式发布验收；P1：功能与运维补齐；P2：后续优化。
- 上述 P0/P1 是对应交付范围的门禁等级，不代表当前先做全部平台；当前先完成 macOS，
  再推进其他 UI 对齐及其发布，Docker 缺项不作为 macOS 开发与验收的前置条件。
- 没有已知自有天气业务算法因语言原因无法移植；外部数据服务、C ecCodes 和平台 UI 是外部边界。

当前验收基线及二进制身份见 `RUST_RUNTIME_CUTOVER.zh-CN.md`；
性能测量范围见 `RUST_PERFORMANCE.md`。
历史 Tauri/共享 Web 与 Rust 的联合逐项清单见 `TAURI_RUST_JOINT_MIGRATION.zh-CN.md`；
它只用于核对现有 Web/HTTP 消费者。正式桌面实现以
`NATIVE_UI_FFI_MIGRATION.zh-CN.md` 为准，不再把 Tauri 作为后续桌面重写主线。

- 产品与 UI 以 macOS 验收基准为准；其他端对齐功能、信息层级、工作流程与状态语义，

### R03 热门城市及区域缓存预热/刷新

- 用户决策 Q05（2026-11-11，已确认）：区域计算时自动生成城市排名，不再另设
  手动预热步骤。设计按同次请求的区域、日期、现象和模式生成对应城市排名，
  沿用现有排名口径；所需输入纳入同一预测前预检，不为排名静默扩大下载范围。
- 已实现：Rust 区域任务使用安装包内置 695 城市目录，复用同一模式、周期、
  事件和输入快照完成 GFS/EC 二次评估并发布独立排名；macOS 原生区域 inspector
  已展示该排名。
- 用户决策 Q06（2026-11-11，已确认）：区域刷新先检查模式周期和输入是否更新；
  输入与请求参数均未变化时复用有效缓存，有变化时进入统一预检弹窗，确认后重算
  区域结果及城市排名。新结果成功后再替换；失败保留旧结果并标明其时间。
  此为用户侧刷新行为；旧只读巡检 API 的兼容语义另行保留/退役，不静默混用。
- 优先级/状态：P1，城市排名随区域计算接线已落地；独立管理刷新 API 仍缺。
- 现状：原生区域任务会从安装包内置 695 城市目录筛选当前区域，
  复用同一周期、模式帧和 CAMS 输入执行 Rust 二次评估并排序；旧热门城市预热、
  national refresh 尚未形成对应原生管理 API。
- 涉及：HTTP 管理路由、任务队列、`desktop_runtime.rs`、缓存身份与管理前端。
- 设计：城市排名并入区域任务，复用输入、进度、取消和缓存身份；
  区域结果与对应城市排名建立同批次引用，避免读取不同周期结果。
  不以独立 `/cache/warmup` 作为用户生成排名的必需入口；
  旧管理 API 是否保留仅在兼容矩阵中决定。
  旧 national refresh 实际只巡检中国近三天 dawn/dusk 六个窗口，返回缓存状态和
  request payload，`queued_count=0`；先保留只读规划语义，不能偷偷变成重计算。
  批量计算复用同一计算入口；按周期/请求去重、限流、支持取消，
  逐项保留 GFS/EC 独立成功或失败；刷新结果原子发布。
- 验收：重复提交不重复下载/计算；失败不覆盖上一份有效缓存；取消不发布成功结果；
  前端能查看每项结果，不只返回“任务已启动”。

### R08 持久任务、恢复和细粒度进度

- 用户决策 Q11（2026-11-11，已确认）：应用或服务意外退出后保留任务记录，
  保留已完成且校验通过的下载；未完成任务标为“已中断”，不自动重新下载或计算。
  用户点击“重试”后重新进入统一预检，复用已有有效数据、补齐缺失部分，再重新计算。
  新结果成功生成前保留上一份有效结果。Rust 核心和 macOS 原生入口已接入，其他
  原生平台仍需按同一合同接入。
- 优先级/状态：P1，Rust 核心任务持久恢复、macOS 历史/事件/手动重试入口已实现；
  结果恢复已改为内容寻址不可变快照 + `result_restore(task_id)`（2026-11-12），
  不再仅复用 `read_cache`。Windows/Linux 原生入口按用户要求暂停；快照保留淘汰、
  真实下载细粒度进度、历史事件分页/按时间淘汰和强杀验收仍缺。
- 现状：桌面任务与通用 HTTP point/regional/nowcast 任务均写入 Rust
  `TaskHistory`；运行中任务在 owner 锁释放后恢复为 `interrupted`，不自动重启。
  进程内注册表只保留取消句柄和尚未释放的完整结果，重启后详情/列表从持久收据恢复；
  大结果仅保存受限 `result_ref`，事件保留最近 256 条。进度仍主要是阶段级，
  不是旧服务的全部细分进度。
- 2026-11-12 取消修复：通用 HTTP 只先写 `cancel_requested=true`，worker 真正结束前
  保持 running 并占用并发许可；退出后才写 cancelled，且不发布成功结果。
  定向测试覆盖取消等待、持久收据、结果抑制和并发许可释放。
