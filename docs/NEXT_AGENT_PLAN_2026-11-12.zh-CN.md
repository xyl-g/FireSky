## CAMS 双路线需求

> 2026-11-12/13 进展：本节之后的工作已由
> [CAMS 双路线提案](CAMS_DUAL_ROUTE_PROPOSAL.zh-CN.md)承接并经用户决定更新——
> 路线 B 整体暂缓（恢复时必须含实况）；路线 A 的 ADS 代理合同已放开（遵循
> 环境代理）；prepare 已默认按所在洲整周期下载 CAMS（见提案 §0 决定记录 3-5）。
> 本节原文保留为路线 B 恢复时的需求基线。

按本轮对话，将用户要选的两种方式解释为：默认使用 ADS 完整廓线；可选使用 Google
Earth Engine CAMS 光谱 AOD 为太阳入射削光提供柱积分约束，同时仍使用 ADS 廓线承载垂直
分布和其他既有气溶胶计算。若实现前发现这与现有用户预期不一致，应先把具体差异写清楚
再确认，不能擅自改成“Google 完全替代 ADS”。

### 路线 A：ADS 完整廓线

- 保持当前默认行为和严格输入合同：ADS AOD550 + 同时次 11 层 `aerext532`。
- 完整廓线用于现有云底高度、太阳入射路径和观测回程路径计算；缓存仍须匹配区域、
  valid time、变量和实际输入身份。
- 不要求用户启用 Google Cloud 项目。ADS 认证、数据集许可和实际上游下载仍须由真实测试验证。

### 路线 B：Google AOD 削光层 + ADS 廓线

- 在当前正式 macOS 设置中让用户明确选择；默认仍为路线 A。选择项必须随预测请求和数据
  预检会话冻结，结果与缓存身份必须记录该模式，不能只改变界面显示。
- 使用 GEE CAMS 469/550/670 nm 多波段值按 Ångström 幂律估算 AOD532。该 532 nm 值是
  光谱估算，不是直接观测波段；保留 469/550 与 550/670 的斜率和差异诊断，不把估算值
  冒充实测或 AOD550。
- Google 数据只负责太阳入射削光层。ADS 仍提供真实垂直廓线和原有观测回程/其他路径；
  必须替换对应入射削光输入或归一化量，禁止在现有 ADS 入射削光结果上再乘一个 Google
  透过率而造成重复计算。
- GEE 影像必须按本次事件的准确 CAMS 有效时刻、区域及起报/预报时效选取；保留影像 ID、
  project ID（非秘密配置）、波段、起报时次、有效时间、导出网格及源文件哈希。禁止取
  集合中随意的第一幅或将邻近时刻静默填入。
- GEE 缺凭据、项目、影像或空间覆盖时，对已选路线明确失败；不得静默退回 ADS。需要回退
  时由用户显式切回路线 A，并在结果 provenance 中记录实际路线。
- 两源时间、空间和质量映射须单独验证：GEE 源网格较粗，不可伪装成 ADS/GFS 网格；区域
  导出需支持大小限制、分块、日期变更线和接边校验。每个模型目标格必须有明确有效值，
  部分覆盖不能报告整区 ready。
- 输出/诊断明确分开 `ADS profile`、`GEE AOD532 estimate`、估算公式和实际消费的太阳入射
  来源；结果不能将混合输入标签写成单一 ADS 或单一 GEE。
- 覆盖所有应用 CAMS 的预测模式，或在 UI 上对暂不支持的模式禁用/明确说明。不能提供全局
  设置开关，却在 nowcast、EC point、regional 或其他路径中被忽略。

### GEE 接入的生产约束

现有 `scripts/download_gee_cams_aod.py` 依赖 `earthengine-api`、NumPy 和 Requests。正式桌面
包和 Docker 目标是不依赖 Python，因此后续实现前必须在设计记录中选择并验证一种认证/请求
边界：

1. 为受支持的本机凭据提供 Rust/原生 Earth Engine 请求实现；或
2. 将 Python SDK 工具限定为用户明确运行的离线导入/诊断工具，不宣称它已成为正式预测源。

不得在未经说明的情况下让生产预测通过 `python3` 子进程调用该脚本，否则会改变正式包的
无 Python 合同。若采用原生实现，需确认 EE OAuth/refresh、token 安全、取消、超时、代理、
导出和 EECU 错误处理；不得把 token、下载签名 URL 或凭据内容写入日志、任务历史或结果。

### CAMS 工作包与验收

1. **合同审计**：检查 `engine/src/earth_engine_aod.rs`、`scripts/download_gee_cams_aod.py`、
   `engine/src/assessment.rs`、`native/src/national.rs`、桌面 FFI/Settings、`desktop_prepare`
   和所有 point/regional/nowcast 消费者。输出一张“数据字段 -> 使用模块 -> 评分路径”表。
2. **设置与来源合同**：定义稳定 enum/版本化 request 字段；默认 ADS；选择、project id 和认证
   状态持久化不含 token。设置变更使结果缓存失效；预检确认后按同一选择准备与评分。
3. **数据计划/缓存**：逐目标 valid time 导出 GEE 区域数据；验证源 identity、网格、掩码、波段、
   hash、尺寸和覆盖；缓存身份包含模式、project、area、影像、时间和版本。支持分块和跨日界线。
4. **评分接线**：仅替换太阳入射削光部分，保留 ADS profile 对垂直高度和观测回程的既有用途；
   对照 ADS-only 确认只影响目标气溶胶项，云场、太阳几何、遮挡和非气溶胶字段不变。
5. **诊断/UI**：展示选择模式、配置/实际使用来源、AOD532 estimate、valid/run/forecast hour、
   覆盖和失败原因。需要实际下载证明时使用明确“测试 Earth Engine”操作，不能把“已配置”当作
   下载成功。
6. **测试**：添加光谱数学边界测试（零值、缺带、非法值、非幂律差异）、源选择持久化、缓存身份、
   过期时刻拒绝、分块接缝、缺块 fail-closed、无回退、取消、失败保留旧结果、混合来源 provenance、
   ADS 路线无回归和两路线 A/B 输入固定的分数差分。
7. **验收**：先用 fixture 做合同/数值测试，再由用户已配置的 Earth Engine/ADS 账号执行真实 point、
   regional 下载和点预测；扩大到实况前先证明该路径实际消费的时次/数据一致。记录网络、排队、传输、
   解码、评分时间和源码身份。真实测试受上游不可用影响时标为“待验收”，不将 fixture 通过写成生产通过。

## 每个 Agent 任务的交付格式

交付时在 PR/回复中列出：

1. 改动模块、数据/错误/缓存合同和明确未支持的范围。
2. 新增或修改的测试命令及结果，标出 fixture、真实上游、目标机分别验证了什么。
3. 真实数据是否运行、上游身份和有效时间；失败是否是本地实现、认证、队列或网络。
4. 源码 SHA / `source_id`，是否重打包，包内引擎是否与源码一致。
5. canonical checklist 中完成、仍待验收和需要用户决定的条目；不能以一次编译或一次预测声明整体迁移完成。
