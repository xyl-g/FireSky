## 交付方向不变

- 正式桌面是原生 UI + Rust FFI，macOS 先验收；Windows/Linux 当前暂停。
- Tauri 桌面冻结为参考；Docker 使用共享 Web + Rust HTTP。
- 生产不启动或回退 Python；旧 Python 代码暂留，替代验收后再清退。
- 点、区域和实况均须预测前预检、按需准备、用户明确确认。
- 主要用于本人及约 2–3 人轻量自托管，不扩展为公网多租户服务。
- 缓存保留由用户分别设置 GFS/EC/CAMS 周期数、卫星滚动天数及报告/地图天数；
  未约定数字默认值，不把示例“5 周期”写成默认。

### HTTP 生命周期和轻量安全

- 通用 HTTP 取消先记录 `cancel_requested`，worker 真正退出前保持 running、
  占用并发许可；退出后才记 cancelled，不发布成功结果。
- 默认只监听 loopback；远程监听须显式开启并配置令牌。
- 页面、API、报告和地图支持 Basic/Bearer；health 除外。
- 校验 Host/Origin，防跨源和 DNS rebinding；令牌文件受大小、类型和权限约束。
- Docker entrypoint 在未显式提供令牌时生成并保存私有随机令牌，不打印令牌。
- 真实 HTTP socket 安全冒烟已执行；不等于 Docker 镜像或浏览器登录弹窗已验收。

### 数据完整性与旧 Web 适配

- `requirements` / `fetch` 验证冻结事件计划，空计划、缺失、损坏均不 ready。
- GFS 解码核对周期/时效，EC 检查完整 bundle 及冻结来源，CAMS 检查有效时刻。
- 旧 Web 数据页不再从库存空数组推断完整，不再把未确认周期误判成更新。
- 未知库存状态但能力可用时允许准备；能力明确不可用才禁用。
- CAMS 不发送不支持的手工 cycle；切区域后丢弃旧请求响应。
- done 缺少严格 readiness 时不显示准备成功；失败不触发旧数据淘汰。
- 这不代替预测前的全科学字段预检，GFS 可解码不等于所有科学字段齐全。

### CAMS 跨日界线及实况范围

- CAMS 单矩形边界明确拒绝未拆分请求，双矩形计划、解码合并和逐侧预检已有实现。
- 合并验证边界去重、11 层字段保真、有效时刻一致性及源身份；
  单侧缺失不能放行，避免旧 min/max 覆盖检查把一侧误认成两侧。
- 未知实况地点不再回落 EAST_ASIA；按实际球面 bbox、光路和气溶胶采样范围规划，
  命名区域只有覆盖充分时才复用原缓存身份。
- prepare/runtime 共用 `area/areas` 一致性验证；修复 wrapped GFS 解码裁剪，
  decoded cache identity 从版本 2 升至 3，避免误用旧裁剪结果。
- 极区可能需要全经度范围，下载成本会增加。没有承诺 Himawari 视场外的观测可用性。

- 模式经度轴改为内部连续经度分支，网格、地形与字段同步重排；观测点、风平流、
  光路和冻结剖面按同一分支采样，公开经度仍规范化，覆盖恰好 ±180° 的边界。
- 普通科学回归及跨界完整 frames 对照已通过；真实双侧上游下载和连续地图仍未验收。
  不能仅凭科学 fixture 推断完整生产跨界预测已经可用。

### 已实现

  OS 进程（重执行测试二进制扮演角色）：

    保留清理释放空间后可重新发布。测试结束自动卸载卷。
- 修复压测暴露的两处真实缺陷，并修订发布/清理租约协议：
  - **在途发布临时文件被清理竞态**：原 `publish` 用匿名 `.tmp*` 临时文件，清理的
    “崩溃残留清扫”会删掉正在写入的临时文件，`persist` 报 NotFound（多进程压测
    复现）。改为 `publish` 全程持有该 sha 的共享读租约，临时文件命名 `<sha>.tmp*`；
    清理对该命名先查租约，被持有则记 deferred，崩溃（租约空闲）才清扫。
  - **租约文件删除破坏 flock 互斥**：删除租约文件后新建的同名租约是新 inode，
    与仍锁着旧 inode 的读者/发布者不再互斥。改为**租约文件永不删除**：0 字节、

    不再连带删租约。
  - **满盘时首次恢复失败**：原 `read` 首次读取需创建租约文件，满盘时 ENOSPC。
    改为 `publish` 时即创建租约文件，恢复只打开既有文件，不需要新磁盘空间。
- `result_snapshot::shared_lease` 公开（与已有 `exclusive_lease` 对称），供系统级
  测试扮演持租约读者；`cache_retention` 新增 `sweep_locked_file`（清扫前试独占
  flock，被持有则延后），用于非快照命名的崩溃残留文件。
- 修复既有跨进程崩溃单测的偶发失败（约 1/25，负载下更高）：子进程 `ready` 信号
  用 `fs::write` 非原子写入，父进程可能在内容写完前读到空/半截 sha，对错误的
  租约文件加锁成功。改为临时文件 + 原子 rename；新增的多进程崩溃测试同样采用
  原子 ready。修复后该单测重复 40 次无失败。
- 全量重复稳定性验证又暴露混合压测两处**测试自身**的时序假设（非产品缺陷），
  已改为确定性断言：
