# Web 与 macOS 展示对齐方案

更新日期：2026-11-13。本文对照原 Svelte Web 页面与当前 SwiftUI macOS 桌面端的用户可见内容，
定义桌面端展示补齐范围。现有 macOS 后端字段审计见
[后端数据与界面展示审计](MACOS_BACKEND_DISPLAY_AUDIT.zh-CN.md)和
[字段映射清单](MACOS_BACKEND_DATA_DISPLAY.zh-CN.md)。本文重点是页面内容和图形表现，不改变评分算法。

## 范围决定

- **区域结果必须在地图上渲染。** 显示 GFS/EC 区域质量场、覆盖范围、网格/缺测、图例和网格详情。
- **单点预测不渲染预测地图。** 单点页面保留位置选择地图，但不增加云场/可烧场预测地图。
- 不要求地图与质量图、逐时台账或剖面图联动。各图/地图的数据、选择器和展示状态独立；
  不要求点击一张图就移动另一张图的游标或时次。
- 原 Web 的图表内容和视觉语义需要在桌面端有对应表达；使用 SwiftUI Charts / 原生绘制实现，
  不把 Svelte 页面嵌进 WebView 来代替原生展示。
- 实况 nowcast 与单点模式预测分开：本方案保留 Web 实况页的卫星/云场可视化需求，
  但其地图仅作为独立实况视图；不与趋势图、表格或剖面联动。
- 没有真实数据的值显示缺测/不可用原因，不以 0、空晴或代理值伪造观测。

## 目标界面

### 单点预测

保留现有原生位置/参数栏、GFS/EC 结果比较和结果分页。概览页使用以下自上而下结构：

1. GFS / EC 质量摘要、档位、最佳时刻、推荐窗口和结果状态。
2. 评分要素分组：云量/可烧云、亮度色彩、入射与观测 AOD、持续时间、置信度语义。
3. “评分组成”分项图：基础云量分、持续时间修正、入射削光、观测对比度等，显示贡献值、
   测量值和方向；按 Web 解释标明哪些几何遮挡已包含在可烧云量、不会二次扣分。
4. 逐时质量与大气趋势图，以及独立的 AOD550 趋势小图。
5. 逐时台账和太阳方向大气剖面继续通过标签页访问；表格与趋势/剖面可以共享本地选择时刻，
   但不联动地图。

质量趋势图保持 0–2.5 固定质量轴。可烧云占比、可烧比例和返程透过率使用 0–100% 比例语义，
采用右轴或与质量分上下对齐的小图，避免不同量纲共用一个未标明坐标轴。线色/线型跟随 Web 的
质量、覆盖、照明、透过率语义；GFS/EC 用稳定颜色/虚线区别。缺测断线，不按零值连线。AOD550
独立展示取值范围、时次和来源。

### 实况分析

保持独立的实况摘要、质量趋势、实况诊断和卫星剖面。补齐 Web 能力已有且 nowcast DTO 实际返回的
卫星观测时间、近/远场云比、纹理/云幕、运动相关性/帧龄/外推时长、雷达回波/降水/可靠度、
几何阻挡和采样覆盖率。按产品可用性分组，不要将某一路 HSD 代理误标为 HCAI 观测真值。

卫星垂直图沿用“距离 × 高度/压力层概率热图”，明确标出 retrieved、unknown、GFS vertical prior
和覆盖比例。若增加实况地图帧，只作独立地图浏览，不与逐时评分、台账或剖面联动。

### 区域预测地图

区域页继续使用 MapKit 和 `frame_data` / `RegionalMapLayers`，而非移植 Leaflet。用户应能在同一地图视图中：

- 选择 GFS、EC 或并排对照；保留地图拖动、缩放、区域绘制和网格显示。
- 在地图上渲染连续质量色带，颜色数值固定映射到 0–2.5；缺测网格保持透明/斜线或空缺态，
  不进入有效网格排行。
- 展示覆盖边界、网格间距、有效/缺测统计和图例。跨 ±180° 区域须保持网格连续、无错缝。
- 点击网格打开原生详情面板；支持网格/城市排名筛选，但不能以列表代替区域地图渲染。
- 地图、图表、逐时表和剖面是独立视图；地图选点不驱动其他视图，其他视图选时也不改变地图。

网格弹窗优先复用区域 API 已给出的峰值质量、事件质量、档位、最佳时间、主导云族、可烧覆盖、
持续时长、AOD 和置信度字段。字段没有进入区域 `points[]` 时，再由后端扩展版本化区域点 DTO；
禁止前端用单点预测或另一模式数据拼接填充。

## 原生图形规范

- 以 Swift Charts 和 MapKit/`MKOverlayRenderer` 实现，不引入 WebView。线条、坐标、图例、单位、数值精度
  和缺测表现与 Web 语义对齐；平台排版可以原生化，不要求逐像素复制。
- 图表需要标题、轴名和单位、图例、最佳时刻标记、明确缺测间隔、可读 tooltip；颜色之外还要有线型/标签
  区分系列。浅色/深色、窗口缩放和辅助功能读数都要可用。
- 质量色带共享 `RegionalPalette` 语义和 Web 的 0–2.5 范围。不能让每次预测自动拉伸色带，否则区域间颜色
  无法比较。
- 横向台账保留列标题、单位、缺测值、排序时序和最佳时刻状态；宽度不足时可滚动，不能截掉字段名称或值。
- 空数据、部分覆盖、引擎错误、缓存快照和不支持字段需有独立状态；禁止用空白图表或 0 冒充成功。

## 后端数据可用性与新增工作

### 可直接从现有报告/剖面读取，通常只需 UI 对齐

- `steps[]` 已包含趋势图和逐时表所需的质量、云量、入射/回程、太阳角度、AOD、压力族/云高、场景等字段；
  先建立逐字段覆盖表，再扩展 `WorkLedgerView` 和 Charts，不复制评分逻辑。
- 点/区域 `cross_section.fields` 含 geopotential height、temperature、RH、cloud fraction/presence/amount、
  liquid/ice、wind、omega、cloud base/top/status，以及 terrain、required illumination 和 theoretical targets。
  macOS 当前 `WorkCrossSectionView` 只画 theoretical target 云底/云顶和照明基准，绘图实现有明确可用数据来源。
- Nowcast `satellite_vertical_profile` 已用于原生压力层概率热图；优先补齐标签、数据状态和视觉语义，不重复造一个不同口径的图。

### 需要先补后端数据合同，UI 不可猜造

- 单点预测的完整云场地图：当前点预测 `steps[]` 没有 map cells，`map_capability.available=false`；按本方案不做，
  避免无效地图工作。
- Nowcast 地图：当前原生桌面没有请求/接收地图 cells，`include_map_cells` 默认关闭；若需要 Web 实况地图，
  单独提案其数据范围、快照容量、地图令牌和渲染合同。此项不影响质量图表/剖面展示。
- 区域网格弹窗扩展字段：先检查 Rust `points[]` 是否已有 Web 所需字段。没有时在 Rust DTO 中增字段和合同测试；
  不用 UI 从图形网格反推 AOD/可烧比例。
- `confidence`、跨模式分歧、模型层云水/云冰等字段只在后端实际计算并声明语义后展示为数值；占位值要显式显示
  “未计算”。

## 实施顺序

1. 建立 Web -> desktop 字段矩阵和截图基线；标记已有字段、原生已绘、原生缺绘、后端缺数、明确不做五类。
2. 先补纯展示且无需新源数据的区域地图图例/详情和单点/实况趋势曲线；同步扩展逐时台账字段。
3. 用现有 `cross_section.fields` 补齐单点/区域温度、RH、云层、地形和日照剖面。图例应说明数值为 GFS/EC
   各自模型场，云层代理的差异不可混在一条曲线上。
4. 完成实况指标组和卫星概率剖面状态一致性；nowcast 地图是否接入独立立项，不阻塞图表内容对齐。
5. 扩展区域 `points[]` 弹窗需要但实际缺少的字段；保证缺测不参加排行和色带渲染。
6. 最后进行 UI 走查和 Rust/Swift 包验收；不将 fixture 截图、已有结果缓存或前端合同测试当作真实数据验收。

## 验收清单

- 选定 Web 和 macOS 同一份点、区域、实况 JSON fixture，逐一比较字段、单位、时间区、缺测/错误态。
- 点结果没有地图覆盖层；位置选点地图仍可用。地图不随趋势图或台账选中时刻变化。
- 区域质量网格真实渲染 GFS/EC 值，统一色带、覆盖范围、缺测、并排比较、点击详情与排行；不只是显示表格。
- 趋势图至少展示 Web 的主质量系列和已有有效比例/因子序列，AOD550 单独成图；模型线型/色彩、缺测断线、坐标精度正确。
- 评分拆解显示实测量、修正量和评分语义；公式只读展示后端计算结果，不在 SwiftUI 重算。
- 单点/区域垂直剖面绘制已返回的压力层字段；温度、RH、云量、地形和照明图例正确，缺测不解释成晴空。
- Nowcast 指标来源、卫星帧时次、雷达时效、profile posterior 和 unknown 状态保持可辨认；不得把 HSD proxy 标成官方云产品。
- 视觉检查 1440×900、1120×720 和窄窗口；浅色/深色；长时间标签、负高度、缺测、全无效、只有一种模型成功。
- 使用图表时键盘和 VoiceOver 可读。地图联动不在验收范围内。

## 非目标

- 单点预测地图渲染。
- 地图、趋势图、逐时台账、剖面之间互相驱动/联动。
- 将 Svelte/Leaflet 嵌入 macOS 作为快捷替代。
- 在原生 UI 重新实现质量算法、补算缺失指标或凭空构建天气场。
- 本文不代表真实 CAMS、跨日期变更线地图或全量 public forecast 合同已验收。
