# 桌面数据工作流

## 定位

- 单点与实况共用观测点，点击“获取当前位置”才申请系统权限。
- 显示系统水平精度；过期位置、拒绝授权和不可用服务不会覆盖原点位。
- 定位后异步补齐海拔与时区，不自动运行预测。
- macOS 使用带定位用途声明的 `.app`。普通命令行 Python 不请求系统定位，可使用地图与搜索。

## 检查与准备

- 单点与区域一次提交 GFS、EC 两个模式，输入区不再要求选择模式。两份独立结果通过结果栏切换，不混合评分。
- 两个模式分别锁定预检周期；缺少任一模式所需数据时先提示准备。执行中单个模式失败保留另一份结果并显示“部分完成”，不会展示旧结果冒充成功。
- 单点、区域与实况在运行前检查本次坐标/范围、日期、现象及数据时效。
- 同时区分本次事件周期、本地周期与上游核验的最新发布周期。离线/启发式周期明确显示未核验。
- 历史事件不强制使用晚于事件的最新周期；经检查的模式周期锁定到随后的准备与计算。
- 每次预测先打开紧凑数据清单；单点/区域仅显示 GFS、EC、CAMS 三行。两个模式各自的 CAMS 空间需求内部保留，缺失清单按范围与有效时刻去重，不重复展示数据源。
- 本地清单不等待上游探测、不解码模式地形；先按元数据和保守事件窗口判断已下载/缺失，上游最新发布状态随后独立更新。缺失时禁用“确定预测”，未核验不冒充最新。
- CAMS 候选路径每次检查只收集一次，先筛选所需有效时间，再判断范围；完整解码校验留在下载后复检和预测引擎中。完整校验仍会拒绝格式错误或不完整的文件。
- 弹窗只显示源状态和简短进度，不展开周期矩阵、文件路径或日志。数据页仍保留完整缓存清单。
- “更新 / 补齐数据”重新核验事件适用周期；最新 EC 所需时效尚未发布时保留较早的可用周期，CAMS 更新可绕过旧周期缓存，但不会把晚于历史窗口的周期用于历史事件。
- 下载完成后重新预检，并保留窗口；只有用户点击“确定预测”才计算。取消、准备失败或下载后仍缺失均不会自动开始；准备期间改参数不会把旧任务结果用于新请求。
- 模式地形可从本地数据读取时按真实地形计算事件窗口；否则预检保留时间余量，计算时仍执行严格校验。
- 实况按选定事件和地点预热相邻 HSD 帧、同周期 GFS 垂直背景及 CAMS。超过实时窗口的未来事件使用模式预测，不伪造卫星帧。

## 数据与设置

- “数据与下载”列出实际原始数据文件、UTC 周期、预报时效、地理范围、占用及未识别文件，可打开缓存目录。
- 该页按最新可用周期下载区域数据；历史事件通过对应预测页准备。
- 发布核验结果只在有限时间内标为最新。文件索引并不替代预测引擎的解码与内容校验。
- 设置仅管理 ADS 凭据和地图供应商；不会把密钥输入混在下载界面。
- 清理操作移动旧文件到 `.cache/.trash`，不是立即释放所有磁盘空间。

## 区域地图

- 所有区域固定使用 `0.25° × 0.25°` 计算网格。
- Leaflet 真实底图上使用 viewport canvas 绘制全部返回网格，不插值、不只绘制排行点。
- 缺测/失败单元单独显示；地图可查看每格数值，排行榜保留前 2000 条并可定位网格。

## 验证边界

自动测试使用本地夹具和模拟上游；模拟网格截图只证明绘制与交互，不证明气象预测质量。真实系统定位授权、ADS 账户权限、上游下载成功与大区域完整评分仍需运行环境验证。
